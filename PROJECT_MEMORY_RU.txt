3. TOUCH x4 — AML-МОД МУЛЬТИТАЧА НА 4 ПАЛЬЦА (папка touch4/)
=====================================================================
- Файл для пользователя: libMultiTouch64.so -> папка mods AML. Лог: mods/touch4_log.txt.
  Настройка: Настройки > Mods Settings > «4-Finger Touch: On/Off» (через SAUtils), сохраняется в
  Android_unprotected/data/com.rockstargames.gtasa/configs/net.helicover.touch4.ini.
- Исходники: touch4/touch4.c (C без libc), touch4/gtasa_offsets.h (смещения из libGTASA
  пользователя), touch4/build.sh (clang --target=aarch64-linux-android21 + lld, заглушки libc/libdl),
  touch4/test_touch4.py (эмуляция arm64 через unicorn на настоящем libGTASA.so: 381 проверка).
  Запуск: sh touch4/build.sh; python3 touch4/test_touch4.py путь/к/libGTASA.so
- Как работает: снимает лимиты 2 пальцев в libGTASA (OS_PointerGetNumber, проверки индексов,
  Points[2] -> 4 записи через GOT, m_nMaxTouches=4), при первом касании через JNI ставит
  Use2Touches=false (APK менять не нужно), сам ведёт все 4 пальца по pointer id
  (MotionEvent.getPointerId) и подаёт их в игру через AND_TouchEvent из хука ProcessEvents.
  Перед любыми изменениями сверяет все байты кода; при несовпадении — «nothing changed».
- v1.0 базовая; v1.1 пальцы по pointer id (не «теряются»), пункт в Mods Settings (ISAUtils слот 3
  AddClickableItem, проверено по исходникам SAUtils 1.6); v1.2 (PR #24) — не нужна новая
  исполняемая память: переходники внутри .so, заглушка multitouch4 = ldr x16,<mt2+16>; br x16.
  Причина v1.2: на телефоне был лог «no executable page near libGTASA».
- Статус: пользователь подтвердил — v1.2 «очень хорошо всё работает».

5. НОВЫЙ ИНТЕРФЕЙС CLEO — ОТДЕЛЬНЫЙ ПРОЕКТ (папка cleo-ui/, ЕЩЁ НЕ НАЧАТ)
=====================================================================
- Желание пользователя (15.11.2026, после беты 3): «Меня бесит синий светлый прямоугольник, хочу что-то красивое, плавное и
  анимированное»; затем: «Переработай всю механику CLEO, исправь все ошибки, измени весь дизайн — супер красивый и пафосный…
  сделай это отдельно от мода вертолёта… встрой поддержку русского языка… раздели отдельной папкой в гитхабе». Стиль:
  тёмное + оранжевый, анимации кнопок. Это НЕ часть Helicover: отдельная папка, отдельные PR, отдельный архив.
- Утверждённый план: AML-мод (.so в папку mods, как Touch x4) поверх CLEO пользователя — меняет только то, что рисуется и как
  реагирует на касания (список скриптов, меню скриптов, кнопка вызова), для ВСЕХ скриптов; русские надписи CLEO при «Русском»
  игры и автоперевод русского текста чужих скриптов (UTF-8 / CP1251) в коды шрифта игры; настройки в Mods Settings (вкл/выкл,
  цвет акцента, анимации). Движок CLEO (закрытый libcleo Blade) не трогаем. Правило безопасности как в Touch x4: при любом
  несовпадении байтов — ничего не менять и написать причину в лог.
- Этапы: Б0 разбор файлов пользователя и отчёт (что заменяю, что невозможно) -> Б1 каркас (build.sh как у touch4, тесты на
  unicorn с настоящими libcleo и libGTASA) -> Б2 вид и анимации -> Б3 русский -> Б4 настройки, README, архив CLEO_UI_….zip.
- БЛОКЕР: нужны файлы пользователя — все .so из папки mods AML (главное — библиотека CLEO: libCLEOMod.so / libcleo.so или
  похожее имя), папка configs (или файл с «cleo» в имени), скриншоты списков файлов в папках mods и CLEO. libGTASA.so уже был.
- Что уже известно: открытая обёртка CLEOMod (RusJJ) над закрытым libcleo; цвет меню по умолчанию «55 127 175 150» (тот самый
  синий прямоугольник), в 32-битной сборке цвет патчится по libcleo+0x1525C; опкоды пальцев 0CB5–0CBD есть только в ней.
  Координаты скриптов 640x448 через CorrectAspect: x_px = (W − 4H/3)/2 + x·(4H/3)/640, y_px = y·H/448; массив касаний Points
  в libGTASA 0x8B4EBC (записи по 0x1C: x, y, состояние; 2 = палец на экране).
- Честные риски (сказаны пользователю): нативный код может уронить игру; экран не виден — вид доводится по скриншотам в 2–3
  захода; объём в разы больше беты 4.
